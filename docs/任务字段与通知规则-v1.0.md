## 一、任务字段清单

| 字段 | 类型 | 必填 | 说明 | 主要使用方 |
|---|---|---|---|---|
| id | String（UUID） | 系统生成 | 主键，创建时生成，永不变更 | 全员 |
| title 事项 | String ≤60 字 | ✅ | 去首尾空格后非空 | A／C／F |
| type 类型 | 枚举（见第二节） | ✅ | 五类，表单下拉选择 | A／F |
| dueAt 截止时间 | LocalDateTime？ | ❌ | **空 = "截止时间待定"**（定版要求支持待定）；同步可后补 | A／E／F |
| courseId 关联课程 | String？ | ❌ | 引用课程表 id；课程删除不级联删任务（见第六节 B 条） | A／B／E |
| completedAt 完成时间 | LocalDateTime？ | ❌ | **null = 待办；非空 = 已完成**；取消完成即清空 | A／E／F |
| source 来源 | 枚举 MANUAL／SYNC／AGENT | ✅ | 定版要求；AGENT 值 Agent 阶段启用 | E |
| externalId 外部稳定 ID | String？ | ❌ | 同步任务去重键。**具体取值待作业通道定位后由 C 补充**（见六-C③）；手动任务为空 | E／C |
| version 版本号 | Long | ✅ | 初始 1，每次成功写操作 +1；写请求必须带 expectedVersion，不匹配即冲突 | A／E |
| manualDirty 手动修改标志 | Boolean | ✅ | 同步任务被用户手动编辑或完成后置位；同步合并时保护置位项（见第五节） | E |

派生状态（**不存储，代码计算**）：待办（completedAt 为空，且 dueAt 为空或未过）／已完成（completedAt 非空）／已逾期（completedAt 为空且 dueAt 已过）。
日期归属一律按**设备本地时区**、00:00 为日界——"今天／明天"、今日截止、本周进度等判定同此口径。
排序、"剩余 X 天"、逾期判定一律由代码计算。

## 三、操作接口（供 A 接入；Agent 阶段复用同一套，不另开写入口）

| 操作 | 签名要点 | 规则 |
|---|---|---|
| 新增 | createTask(title, type, dueAt?, courseId?) | title 非空≤60；courseId 存在才可关联；**首个带 dueAt 的任务保存成功后**才申请通知权限（拒绝不影响保存） |
| 编辑 | updateTask(id, expectedVersion, changes) | 版本校验；按第四节取消并重建提醒（任意字段变更均重建）；置位 manualDirty |
| 完成／撤销 | setTaskCompleted(id, completed, expectedVersion) | 完成：completedAt = 完成瞬间（设备本地时间）；撤销：清空 completedAt；完成→取消该任务全部提醒，撤销→按规则重建 |
| 删除 | deleteTask(id, expectedVersion) | 同时取消提醒；v1.0 物理删除，不做回收站；**同步任务另记墓碑，见第五节** |
| 查询 | getTasks(filter) | filter：type／courseId／日期范围／状态；**排序：待办按 dueAt 升序，dueAt 为空的任务排最前并标"截止待定"**；逾期任务保留在列表并标"已逾期" |

错误反馈（统一"错误码 + 人话文案"，失败时界面恢复原状态，不给部分写入）：

- `TASK_NOT_FOUND` 任务不存在，请刷新后重试
- `EMPTY_TITLE` 请填写任务名称　／　`TITLE_TOO_LONG` 任务名称过长（≤60 字）
- `VERSION_CONFLICT` 内容已被修改，请刷新后重试（**不静默覆盖**）
- `COURSE_NOT_FOUND` 关联的课程不存在

## 四、通知与提醒规则

1. **权限时机**：首个带 dueAt 的任务保存成功后申请通知权限；拒绝后任务功能完全可用，仅无提醒（定版要求）。
2. **默认提醒时机**：截止前 24 小时、截止前 1 小时各一次（统一规则，不做每任务自定义，见第七节）。
3. **取消重建**：编辑（**任意字段**——标题改了提醒文案也要变）、完成、删除时，按任务 ID 取消全部旧提醒再按需重建——**编辑和完成后不得残留旧提醒**（定版原文）。
4. **过期**：已逾期任务不再发提醒，保留在列表并标"已逾期"。

## 五、与同步、Agent 的并发约定（供 E）

- **合并规则**：source+externalId 相同视为同一条 → 同步更新其解析字段；但该任务的 completedAt 非空或 manualDirty 已置位时，同步**不得覆盖**（定版要求：不覆盖用户手动修改与完成状态）。
- **版本并发**：手动、同步、Agent 三方交错时一律 expectedVersion 校验，冲突即报错重读，不静默覆盖（对应 R05）。
- **重复请求**：写接口预留 requestId 参数，相同 requestId 只生效一次（对应 R04，Agent 阶段启用）。
- **部分成功**：课表成功／作业失败分开标记，作业失败不影响任务页完全可用（定版要求）。
- **删除与同步**：用户手动删除的同步任务，把其 (source, externalId) 记入**墓碑**，后续同步不得重建——否则下次同步会把它复活。墓碑对用户不可见，不参与列表与统计。

## 六、对接边界（定稿）

- **A**：① 待定截止任务排在"近期截止"最前并标"截止待定"，首页"紧急任务"包含待定任务；② 类型五类、表单默认"课程作业"；③ 错误文案风格 —— 均已确认。
- **E**：① 表结构与唯一约束（source + externalId）；② manualDirty 用任务级标志（不做字段级追踪）；③ version 递增由业务层统一负责 —— 均已确认。
- **C**：① 解析结果按第一节映射，解析不了的字段允许为空、**不算失败**；② 失败粒度 = 模块级（课表／作业分开报）—— 已确认。
  ③ **待补充事项**（非确认项）：`externalId` 取作业链接还是作业编号，待作业通道定位后由 C 补充。此前同步任务不启用 externalId 去重，不影响手动任务与建表。
- **F**：① completedAt = 设备本地时区、完成瞬间，取消完成即清空；② expectedVersion **入契约**；③ 本周进度分母**不含**待定截止任务（无 dueAt 无法归周），24h 临期、48h 集中等时间类规则同样不含待定任务 —— 均已确认。
- **B**：课程删除时关联任务保留 courseId 并显示"课程已删除"，不级联删除 —— 已确认。

## 七、开放问题（本版不拍板）

1. 每任务自定义提醒时间（当前统一 24h／1h）；
2. 待定截止任务的默认提醒（建议：无 dueAt 不提醒，仅列表可见）；
3. 回收站／软删除（当前物理删除）；
4. `externalId` 具体取值（等作业通道定位，见六-C③）。
