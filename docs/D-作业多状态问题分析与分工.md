## 一、问题定义：三层叠加，不是一个 bug

| 层面 | 决定者 | 事实 |
|---|---|---|
| ① **模块选型**：MYSTU 同时存在两套 Moodle 作业模块——老 `assignment`（作业 2.2）与新 `assign` | 老师建作业时选择 | 两套在首页 HTML 的类名、信息标签、状态文案**都不同**（详见第二节）；**当前解析器只认老模块** |
| ② **提交状态**：未提交／草稿／已提交／需重新提交，外加小组语义（「我的作业：还未提交」） | 系统记录随操作变化；**组内谁提交、补交通道给谁用，由老师配置** | C 已归一 5 种状态透传（`ImportedTask.schoolSubmission`）；但「是否适用于我」页面读不出，App 不可判定 |
| ③ **总览可见性**：首页只展示「需要留意」的子集，且**随时间波动** | 系统启发式＋缓存 | 11:22 抓页有 WEB应用技术（作业已解析）；16:39 整门课消失（截图 01）；16:42 恢复且排最后（截图 02）。操作系统的作业 11:22 不在、16:39 在。**同一页面两次快照内容不同** |

## 二、量化证据：解析器漏抓 4/6（P1，必修）

11:21 真机抓页统计（D 本机留存，C 出脱敏 fixture 后可复现）：

| 模块 | 首页条目数 | 解析器现状 |
|---|---|---|
| 老模块 `<div class="assignment overview">` + `mod/assignment/view.php` + 「截止时间:」 | 2 条（WEB应用技术的两次作业） | ✅ 已解析 |
| 新模块 `<div class="assign overview">` + `mod/assign/view.php` + 「到期日期:」+ 状态前缀「我的作业：」 | **4 条（高级算法：中期检查×2、项目最终汇报×2，全部「我的作业：还未提交, 未评分」）** | ❌ **全部漏抓** |

漏抓根因（`app/src/main/java/com/coursekeeper/school/MyStuTaskParser.kt` companion）：
1. `ASSIGNMENT` 正则只匹配 `assignment overview`；
2. `ASSIGNMENT_ID` 只匹配 `mod/assignment/view\.php`；
3. 截止时间解析只认「截止时间:」，不认新模块的「到期日期: 2026年09月26日 星期六 00:00」；
4. 新模块状态带「我的作业：」前缀与「未评分」尾缀，归一前需清洗。

## 三、成员 D 的五条观察 → 逐条归因（用户手机反馈，不宣称已独立复现全部）

| 观察 | 归因 |
|---|---|
| 总览两次对比，WEB应用技术整门课消失/重现且排序漂移 | 层面③：首页缓存/渲染波动，真缺陷但随机 |
| 高级算法的作业从未入 App（多次测试） | **层面①解析缺口**（上文量化 4 条全漏），非数据层问题 |
| 逾期未交，首页仍有「提交作业」图标提醒（高级算法/软件工程） | 层面③提醒规则不透明：小组作业「我的作业：还未提交」会持续展示 |
| 软件工程 3 条提交通道，只漏 1 条补交，首页提醒却消失了 | 层面③：过期条目按规则移出提醒，刷不回来 |
| WEB应用技术=理想态（未截止+未提交+首页展示） | 三层同时友好，不是常态 |
