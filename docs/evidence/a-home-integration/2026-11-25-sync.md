# A 第四周同步交互验收

日期为 2026-11-25，开发基线为 main `b1309fa`。本轮补齐下拉刷新、同步失败重试和前台同步生命周期。测试证据采集于提交前，`summary.json` 中 `changesCommittedAtCapture=false` 描述采集时点，当前提交与上传状态以 Git 记录为准。

## 完成内容

1. 首页支持下拉刷新及可访问的“刷新”按钮，接 E 的 `synchronize(force = true)`。没有学校连接或模块登录已过期时，入口交给 C 的登录弹层。
2. 离线、错误与部分成功横幅提供“重试同步”。详情页也可重试，原先本地读取失败的“重试”继续只重读本地数据。
3. 每次 Activity 进入 RESUMED 后，待本地缓存可读且学校已连接时调用 E 的 `onForeground()`，复用其会话检查和 30 分钟节流。登录反馈及导入阶段暂停自动触发。
4. `HomeSyncController` 将自动与手动刷新保存在 ViewModel 作用域，旋转不终止正在执行的刷新。手动重复操作合并，自动同步期间的手动请求保留一次强制同步。登录导入由 C 的弹层等待结果，弹层取消时会取消该次导入并等待清理。
5. 登录后强制同步先取消并等待已有请求清理，使用新会话重新同步。退出登录会取消并等待同步结束，再清除学校选择和 Cookie。退出期间学校入口禁用，登录与退出的会话修改串行执行。
6. 复核修正了关闭 WebView 后的状态判断。C 可保留 WebView 步骤用于重开弹层，该步骤允许首页继续同步，实际导入中的 Feedback／Importing 才暂停触发。

同步中的课程、任务、版本及最后成功时间继续来自 E 的持久化快照。B 的日期规则、C 的学校解析、D 的任务维护和 F 的统计仍由各自模块提供。
