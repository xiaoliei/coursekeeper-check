## 二、门／排课条目／节（核心口径）

这三个词现在混用，是 A 的“今日课程数”和 F 的压力指数算错的根因。定义如下：

| 概念 | 定义 | 数量关系 |
|---|---|---|
| **门**（课程） | 一个教务课程编号 + 一个学期 = 一门；手动课没有编号，按记录 id 算一门。同编号多教师、多地点、多段周次仍是**一门**；同名不同编号算**两门** | 1 门课 = N 条排课条目 |
| **排课条目** | 课程 × 星期 × 节次区间 × 周次集合 × 地点 × 教师。跨节次算 **1 条**；同一门课不同周次分段（4-7 周与 8-16 周）算 **2 条**（通报实测：见过一门课 6 条） | 1 条条目 = K 节 |
| **节** | 一天 13 节中的一节；一条条目占 `endPeriod - startPeriod + 1` 节 | — |

由此固定四个数字的口径：

| 指标 | 单位 | 计算 | 使用方 |
|---|---|---|---|
| `todayLessonCount` 今日课程数 | 条目 | `dayOfWeek` = 今天 且 `weeks` 含本周 的条目数；同一课程不同时段分别计数 | A 首页 |
| `todayPeriodCount` 今日节数 | 节 | 上述条目 `(endPeriod - startPeriod + 1)` 之和 | F 压力指数 |
| `weekCourseCount` 本周课程数 | 门 | 本周有任一条目生效的**不同 courseId** 数量 | A 首页、F 看板 |
| `weekEntryCount` 本周条目数 | 条目 | 本周生效条目总数 | F 类型/分布 |

补充规则：

- 以上四个数字的口径与 F 草案第一节一致（`todayLessonCount` = 今日排课条目数、`weekCourseCount` = 本周不同课程数）；F 确认或修订后**以 F 为准**，B 只改实现。**注意 `todayPeriodCount`（按节求和）是 B 新提的，F 草案里没有这一项**，F 若不要，B 只保留条目数。
- 跨节次的课按 1 条计，不按节数拆成多门；`4-7 周` 与 `8-16 周` 两条同课程条目在各自周内各算 1 条，同一周内不重复。
- 空数据：无排课显示 0（不是“暂无数据”）；学期未设置不算 0，见第五节。
- 停课／假期本期如何处理见第十节开放问题 2。

## 三、周次表示与教学周

**教学周定义**：`startsOn` **归一化为周一**（来源日期不在周一时取该周周一）；第 1 周从 `startsOn` 所在周开始，第 n 周 = `startsOn + 7×(n-1)` 起的周一至周日。日界 00:00、设备本地时区（与 D 的 v1.0 一致）。

**周次用集合，不用区间。** 两种表示同时存在，写入时由同一个函数生成，必须一致：

| 表示 | 形式 | 用途 |
|---|---|---|
| 位图 | `Long`，第 n 周 → bit(n-1) | 存储与计算（包含判断、交集、冲突） |
| 文本 | 升序、相邻合并、区间用 `-`：`1-16`、`9,11-13`、`4-7,8-16` | 展示、日志、人工核对、C 的解析输出 |

示例：`9,11-13` → bit8、bit10、bit11、bit12 → `7424`。

规则：

1. **单双周**不再单设字段：单周 = `{1,3,5,…}`，双周 = `{2,4,6,…}`，是位图的子集；导入时可识别 `(单)`／`(双)` 字样转成位图。
2. **非连续、分段**天然支持（这正是实测数据的要求），不要退化成起止区间。
3. **越界**：周次 < 1 或 > `weekCount` → 丢弃该段，记一条字段级警告，**整条不算解析失败**（与 C 的“单字段为空不算失败”一致）。
4. **学期中课表会变**：同一条排课重新同步时按第八节去重键命中后**就地更新周次**，不新增一条；周次拆分（`4-16` → `4-7` + `8-16`）表现为原条目周次收窄 + 新增一条。
5. **跨学期**：一门课只属于一个学期；下学期同名课是新记录。

## 四、节次与时间

1. 一天 **13 节**（以学期节次表为准，默认 13），节次号 1–13，不可跨天。
2. 节次→具体时刻以教务处官方《上课时间对照表》为准，由 B 整理成 `PeriodRecord` 初始数据。**在时间表落地前，界面只显示节次号（如“第 3-4 节”），不显示编造的钟点**。
3. **冲突判定只用星期、节次号、周次集合，不用时间**。时间只用于展示与“距上课还有 X 分钟”。
4. 节次时间允许用户修改（换校区／夏令时等），修改后只影响显示，不改变任何周次或冲突结果。
5. 上午／下午／晚间只是展示分组，不参与计算。

## 五、学期配置与缺失处理

| 情况 | 行为 |
|---|---|
| 校历可解析 | 用校历的 `startsOn`、`weekCount` 作默认值，用户可改 |
| 校历读不到 | `startsOn` 置空，**不猜**；首次进入课表页询问用户“本学期第 1 周从哪天开始” |
| `startsOn` 为空 | `CourseService.today()` 返回 `NoSemester`；课表页显示“请先设置学期起始日”+ 设置入口；首页今日课程显示“待设置学期”，**不显示 0**（0 会被误读成今天没课） |
| 今天不在任何学期内 | 返回 `NotInTerm`，提示“当前不在教学周内”，仍可切周查看其他学期 |
| 用户修改 `startsOn` | 所有周次重新映射，**不修改排课数据**（排课存的是周序号，不是日期） |

`weekCount` **建议默认 20（待全体确认，校历可读时以校历为准）**；多学期并存时，当前学期 = 包含今天的那个。

## 七、错误码与校验

统一“错误码 + 人话文案”，失败时界面恢复原状态，不给部分写入：

- `COURSE_NOT_FOUND` 课程不存在，请刷新后重试
- `EMPTY_COURSE_TITLE` 请填写课程名称　／　`COURSE_TITLE_TOO_LONG` 课程名称过长（≤60 字）
- `SEMESTER_NOT_SET` 请先设置学期起始日
- `WEEK_NOT_IN_SEMESTER` 当前日期不在教学周内
- `INVALID_PERIOD_RANGE` 起始节必须小于等于结束节
- `INVALID_WEEK_RANGE` 周次超出本学期范围
- `VERSION_CONFLICT` 内容已被修改，请刷新后重试（**不静默覆盖**）
- `SCHEDULE_CONFLICT` 该时段与“××课”重叠（**提示，不拦截保存**）

> 这些是 **B 服务层的错误码**。E 的 `DataError` 目前只有 `COURSE_NOT_FOUND`、`INVALID_RECORD`、`VERSION_CONFLICT` 等，`validateCourse()` 现在抛的是 `INVALID_RECORD`；B 在服务层做映射，**不要求 E 改枚举**。`SEMESTER_NOT_SET` / `WEEK_NOT_IN_SEMESTER` 是读侧状态（`TodayResult.NoSemester` / `NotInTerm`），不是异常。

## 八、冲突与去重

**冲突**：两条排课条目满足 同一 `dayOfWeek` + 节次区间相交 + 周次位图相交 + 不同 `courseId` → 冲突。同一课程同时段、但地点或教师不同 → 视为数据异常，提示复核（不算正常排课）。

**不冲突**：同一门课同一时段不同周次（4-7 与 8-16）→ 不重叠即不冲突；同一门课同一条目在导出中被多行重复（跨大节重复）→ 先去重，不是冲突。

**冲突处理**：允许保存，保存后提示并可复核（验收要求“冲突检测可复核”）；不静默丢弃、不自动改周次。

**同步落库方式（已按 E 现有实现确认）**

- **课程**：`externalId` = 教务课程编号，`(source, externalId)` 去重 + 墓碑，E 已实现，B 不改。
- **排课**：**不做条目级去重键**。`replaceSchedules()` 整门课先删后插，条目 id = `nameUUIDFromBytes("$courseId:${fingerprint(draft)}")`：
  - 未变化的条目 id 不变 → A 用 `scheduleId` 做列表 key、冲突定位不会抖；
  - 变化的条目换新 id，消失的条目随替换删除，**不会留陈旧条目**；
  - 因此不需要 externalId、不需要部分唯一索引，也没有“教师一改就新增”的代价。
- **曾要求 E 同步改的两处，v3 已确认落地**：`fingerprint(ScheduleDraft)` 已覆盖周次位图、规范文本、星期、起止节、地点与条目教师（两条只在周次/教师上不同的排课可同时保存，不会算出同一 UUID）；`validateCourse()` 改为校验位图非空、文本一致、星期/节次区间合法、已关联学期时周次在学期范围内。**B 的写侧只需保证提交前位图与文本同源。**
- 课程唯一约束的跨学期问题仍在，见开放问题 6。
