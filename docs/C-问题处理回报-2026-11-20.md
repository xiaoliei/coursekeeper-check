## 三、C-01 导入协程取消后残留"正在读取"状态

**修复**（`school/SchoolLoginController.kt`）：`onLoginSuccess` 捕获 `CancellationException` 后，若状态仍在 `Feedback`/`Importing`，先复位到 `SelectSchool` 再重新抛出；若用户已主动 `backToSelect()`（点"关闭"），保持其选择不覆盖。旋转、退出页面等取消路径不再残留"正在读取学校数据"。

**验证（单测，`SchoolLoginControllerTest` 新增 3 例）**：

| 场景 | 结果 |
| --- | --- |
| 反馈阶段取消 | 复位到选校页 |
| 导入阶段取消（afterLogin 挂起中取消） | 复位到选校页，不残留 `Importing` |
| 用户点"关闭"后协程再被取消 | 保持选校页，不被覆盖 |

**仍有限制**：清单要求的**设备复验未做**——需在"登录成功反馈"与"正在读取数据"两个阶段分别验证旋转、系统返回、点弹层外部，并确认已有课程/任务保留。按清单第四节的验收条件，该项列为待办。

## 五、CD-01 学校已提交作业仍显示逾期（C 牵头，D／E 协作）

**C 侧处理（`school/MyStuTaskParser.kt`）**：解析 `div.details` 原文并归一为 `schoolSubmission`，经 `ImportedTask.schoolSubmission` 透传：

| 页面文本 | 归一值 |
| --- | --- |
| 已提交 | `SUBMITTED` |
| 还未提交 / 未提交 | `NOT_SUBMITTED` |
| 草稿 | `DRAFT` |
| 需要重新提交 | `REOPENED` |
| 其他 / 空 | `UNKNOWN` / null |

C **只透传状态**：不写本地完成（`completedAt`）、不改 D 的逾期判定、不把提交状态当关联键。脱敏样例 `mystu-dashboard.html` 同时含"已提交 / 还未提交"，测试断言两种状态；`draftsAndReopenedStatesAreDistinguished` 覆盖样例外的草稿/重交/其他三种文本。

**待 D/E**：学校"已提交"在任务页如何展示、是否从本地待办移出、与手动完成／恢复待办的关系；如需持久化，由 E 提供同步字段与合并规则（须保护用户手动完成，`manualDirty` / `completedAt` 优先）。R-01 按清单不列为缺陷；C 在核对 CD-01 时将"组员无需本人提交"的样例留作回归。

**仍有限制**：用户反馈的那条作业尚未对照真实页面核验（清单第八节的提醒保留）；上述归一映射基于脱敏样例与实测页面文本，Moodle 其他状态文案（如"逾期提交"）遇到时按 `UNKNOWN` 兜底，不会误判。
