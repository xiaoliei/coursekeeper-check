## 五、证据规范

1. 截图 + `dumpsys` / `logcat` 文本，放 `docs/evidence/<成员>-<主题>/`，或交接轮次的 `evidence/`；

3. 每条记录必须能追到证据文件；暂时没有的标「待补证据」。

## 六、维护与上传规则

1. **行级所有权**：本表是团队「一份 md 一个作者」规矩的**唯一例外**——每一行归写它的人，
   谁改谁维护。只能追加自己的行、或修改自己的行；**不改别人的行**（要改别人的结论，
   先在群里问原记录人）。
2. 谁在真机上验了新场景，就往 §二 加一行；**必须带证据路径**，暂时没有的标「待补证据」。
3. 明细不复制进本表，只放链接；同一场景的细节改动在原文档更新，本表只在**结论变化**时改。
4. 模拟器结果不得写进 §二（放 §三）。
5. **上传**：本表随代码走团队仓库 `docs/`，跟 main 一起提交；每次新增/修改后在群里说一句
   （例：「真机总表 +1 行：荣耀拒绝权限」），方便原记录人复核。
6. 合并冲突时保留双方的行；确需撤回（如误报更正），**在原行标注「已撤回 + 原因」，不整行删除**。
7. 每次准备合并 main 前，若本轮有真机结果，顺手补一行——**不留只在对话里的结论**。
