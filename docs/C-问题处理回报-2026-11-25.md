## 二、CBE-01 导入作业自动关联课程

### 2.1 为什么不能直接映射

MYSTU 课程 ID（`course/view.php?id=1001`）与教务课程编号（`A01CIP`）是两套编号，页面不提供交叉引用。此前的实现因此把 `courseExternalId` 留空、只透传 `sourceCourseId` / `sourceCourseName`，任务页显示“未关联课程”。现在补的是**可行的确定性映射**，不是把数字 ID 冒充编号：

- 不按数字 ID 猜测（`1001` 不等于 `A01CIP`）；
- 不做子串或编辑距离等模糊匹配（“高级算法导论”不匹配“高级算法”）；
- 命中多条不同课程时判为歧义，保持未关联，交给用户手动选择。

### 2.2 映射规则（`data/sync/CourseLinker.kt`）

输入是学校侧课程名（如 `[2026秋] 应用密码学 方若宇`）与本地已同步的教务课程（外部编号 + 课程名）：

1. 去掉开头的学期标签：`[2026秋]`、`［2026秋］`、`【2026秋】`、`（2026秋）`、`(2026秋)`；
2. 生成两个候选名：去标签后的完整名，以及去掉**末尾空格分隔**的教师名（`应用密码学 方若宇` → `应用密码学`）。括号里的教师名**不**剥离（`应用密码学（方若宇）` 保持不匹配，避免把“（双语）”“（一）”这类限定词误剥）；
3. 候选名与本地课程名各自规范化后比较：去掉空白（含全角空格）与常见中英文标点、统一小写，**完全相等**才算命中；
4. 命中 0 条 → 不关联；命中多条不同课程（同名不同课，或两个候选名指向不同课程）→ 不关联。

### 2.3 落点与行为

映射在 **E 的合并层**（`data/sync/SyncMerge.kt` 的 `mergeTasks`）执行，适配器仍不读库：

- 适配器只透传学校侧来源信息，符合“适配器内不直接改库”；
- 合并层已有 `manualDirty` / `completedAt` 保护：用户手动改过关联的任务整条跳过，自动映射不会覆盖用户选择；
- 只对**本次同步来源为 SYNC** 且带外部编号的本地课程建候选；用户手动新建的课程没有外部编号，不在自动映射范围内（可手动关联）；
- 显式 `courseExternalId` 仍然优先；没有显式编号时才算课程名；
- 已经自动建立关联后，若学校改名导致不再唯一命中，**保留原关联**（不抖动、不清空）；任务被删除或课程被撤时，沿用既有墓碑/悬挂关联规则。

## 三、历史作业补抓与缓存消费（P2）

### 3.1 问题

MYSTU 首页只列“需要留意”的作业。作业一旦被学校标为已提交、或截止较早，就会从首页整条移出；如果首次导入时它已经不在首页，本地也从未缓存过，就再也补不回来。D 已在真机确认：**每门课都有 `mod/assign/index.php?id=<课程ID>` 索引页，科目内可见本学期全部历史作业**。

### 3.2 实现

- **配置**（`school/SchoolCatalog.kt`）：`SchoolInfo.taskIndexUrlTemplate = "https://my.stu.edu.cn/courses/campus/mod/assign/index.php?id={id}"`；为 null 的学校不补抓，行为与旧版一致。
- **缓存消费**（`school/WebViewSchoolAdapter.kt`）：注入 E 的 `repository.knownSourceCourseIds(schoolId)`；补抓对象 = 本次首页课程 ∪ 历史见过课程，**首页本次没出现的课程优先**（历史作业最可能藏在整课被移出的情况里）。
- **请求预算**：每课 1 请求；最多 12 门课；总预算 6 秒；单请求连接 3s / 读取 4s（`SchoolHttp.get` 新增超时参数，阻塞读只能靠 socket 超时兜底）。仍属“打开时全量拉取”，不引入轮询；整体落在 E 的 30 秒模块超时内。
- **解析**（`school/MyStuTaskParser.parseTaskIndex`）：按**行内作业链接**定位，与首页同一稳定 ID 规则 `mod/assign(ment)?/view.php?id=`；链接文本为标题，行内其余文本解析到期日期与提交状态。不依赖表格类名或列顺序，老 `assignment` 模块混排也能识别；`index.php` 链接无作业 ID，不导入。
- **合并**：与首页结果按 `externalId` 去重，**同 ID 保留首页内容**（首页是最新快照），缺 ID 条目按内容折叠；不改变 `sourceCourseIds` 记账。
- **降级**：单课请求失败/超时/登录页 → 只跳过该课；连续 2 门课都解析不到作业行 → 视为索引页结构与预期不同，本轮停止，避免白耗请求；首页结果照常成功返回。

### 3.3 仍有限的边界

- **索引页结构未用真实样例校准**：真实索引页尚未抓取，解析器按“行内 `view.php?id=` 链接”的宽松规则实现；真实结构若不同，结果是 0 条 + 停止，**不会误导入**，但也补不到历史作业。拿到脱敏索引页后需按实际结构补一条 fixture 并复核列语义（尤其“到期日期”与“提交状态”）。
- **老模块索引页路径**：老 `assignment` 模块的索引页路径可能不是 `mod/assign/index.php`。当前只按配置模板抓新模块路径；若老模块课程在索引页 404，补抓对该课无效（首页解析不受影响）。
- **账号与学期范围**：`school_course_cache` 是“历史发现记录”，不做账号分区、不代表当前学期名单；换账号或跨学期时可能补抓到旧课程。该项与“跨账号隔离”“跨学期身份”同为已登记边界，本轮不扩大。
- **请求量**：课程多时按上限 12 门/次同步；超出的课程本轮不补抓。是否放宽由 D 的真机验收数据决定。
