# A 模块 Android 示例工程验收记录

验证日期：2026-11-08。版本：0.1.0，包名：`com.coursekeeper.a.demo`。

本次交付是可以独立运行的 A 模块开发样例，包含导航、首页、公共组件和交互演示。完整课表、任务管理、统计、学校同步、持久化和 AI 仍由团队按任务书分阶段实现。

## 实际验证环境

- Windows；Android Studio 2026.2.1 自带 JBR 25.0.3。
- Gradle 9.6.0、AGP 9.4.0、Kotlin／Compose Compiler 2.2.10、Compose BOM 2026.02.01。
- compileSdk／targetSdk 37，minSdk 26，Build Tools 36.0.0。
- 独立 Android API 37 模拟器，x86_64、1080 × 2340、440 dpi；竖屏、横屏及 1.3 倍字体。
- 测试使用专用虚拟设备，未改动原有 Android 工程和用户模拟器数据。

## 构建及自动化结果

| 检查 | 实际结果 |
|---|---|
| `:app:assembleDebug` | 成功生成并安装 Debug APK |
| `:app:testDebugUnitTest` | 9 项通过，0 失败，0 跳过 |
| `:app:assembleDebugAndroidTest` | 成功生成测试 APK |
| 模拟器 instrumentation | `OK (3 tests)`，最终复核耗时 8.989 秒 |

9 项逻辑测试覆盖数字与筛选一致、完成／撤销、重复完成、空数据新增、唯一 ID、本周统计边界、异常状态下本地操作、重新登录保留修改、连接学校保留手动任务、输入校验及未知任务 ID 拒绝处理。多个断言合并在同一测试中。

3 项 Compose 测试覆盖四页导航、首次启动跳过登录、离线添加任务。测试源码分别在 `app/src/test` 和 `app/src/androidTest`；原始结果摘要在 [逻辑测试 XML](evidence/unit-tests.xml) 与 [设备测试输出](evidence/device-tests.txt)。

本次使用 `adb shell am instrument -w com.coursekeeper.a.demo.test/androidx.test.runner.AndroidJUnitRunner` 运行已安装的测试 APK。工程也提供 `gradlew.bat :app:connectedDebugAndroidTest` 入口；没有把该 Gradle 命令写成已执行结果。

Compose 传递依赖原本引入 Espresso 3.5.0，在 API 37 上触发测试框架反射错误。已显式升级测试依赖到 3.7.0 并重跑通过。修复依据为 [AndroidX Test 官方发布说明](https://developer.android.com/jetpack/androidx/releases/test#espresso-3.7.0)。这项调整仅用于设备测试。

## 模拟器界面操作复核

- 首页完成 Java 实验报告后，今日已完成从 1 变为 2；点击“撤销”后回到 1，任务恢复待办。
- 数据页显示本周完成 1 / 4，与首页初始假数据一致。
- 正常、离线、登录过期、部分成功、空数据、首次启动六种场景均可打开；异常提示不移除底部导航和手动添加入口。
- 首次启动可选择“先手动使用”，进入空数据首页。
- 从首页“今日已完成”进入任务页后，横竖屏切换保留筛选和完成状态。
- 1.3 倍字体下检查首页及添加弹层；空名称提交会显示错误，取消可关闭弹层。
- 软键盘弹出后输入 `NextStepDemo`，保存成功，并在任务清单中找到该任务。
- 视觉检查发现首次启动标题行距偏紧，已增加行高，重新编译安装并复核截图。
